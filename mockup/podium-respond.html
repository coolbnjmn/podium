Respond to a waiting session from Podium

When a session stops to ask something, the amber band gets a Respond button. It opens the Activity modal, where you can answer the question, approve or reject a plan, allow or deny a tool, or send a new message or /clear. The answer goes to the session through podium-reporter. The terminal or desktop app still works the whole time, and whichever answers first wins. Section 3 shows the modal in every case. To click through one yourself, pick a kind of wait and a state, then press Respond on the card.

Rules for the button

  • Shown only while the session waits on you, and only when every switch in section 5 is on.
  • One name in every case: Respond. The modal says what kind of answer is needed.
  • Not on a card that waits on background work (blue band), since nothing there needs you.
  • The card's own click target is unchanged: it still opens the orchestrator page. Respond opens the modal straight from the wall.

2. The orchestrator page

The same band, and the same button, is the last row of the summary at the top of the page. The Expand button on the orchestrator's Activity panel opens the same modal, so you can send a message even while the session is still running (it waits in a queue until the session is idle).

3. The modal, case by case

Each frame is the modal as it opens from Respond in that case, with the feed cut to its last few rows. The page behind it is blurred in the real thing. To click through one, use the controls at the top and press Respond on the card.

4. What the terminal shows

podium-reporter writes one line above the prompt while the question is also open in Podium, and one line in the transcript when it was answered from there, naming who answered. Someone at the terminal is never surprised by an answer they didn't give.

While the question is open. The terminal dialog works as usual.

After an answer from Podium. The dialog closes by itself.

5. The switches

Off by default, and every one is needed. The Admin decides whether this server may send anything; the person running the session decides how much their session accepts, and can always say no. Answering also needs the activity feed, which already has both kinds of switch.

Respond from Podium Admin > Settings > Feature flags. Lets people answer and message the sessions they own. Each answer is written to the admin log with who sent it.
podium-reporter option respond Set in Claude Code with /plugin configure podium-reporter@eengelking-marketplace. What this session accepts from Podium:
  • offNothing. The default.
  • questionsAnswers to questions, and new messages while idle.
  • questions-and-plansThe above, plus approving or rejecting a plan.
  • everythingThe above, plus allowing or denying a tool (allow once only), and /clear, /compact, /model, /effort.

6. Still to test before any code

  1. Answering a question from a mod. Whether a tool.call hook on AskUserQuestion can return the answer and close the open terminal dialog at the same moment.
  2. Messages in place of an answer. How a message sent in place of an answer, and a typed answer, reach Claude (the tool's response and answers fields).
  3. Plan approval. Whether the mode can be chosen on approval, and whether "keep planning" can carry your feedback.
  4. /clear from a mod. Whether $.command.run runs it, and how Podium follows the session to its new id.
  5. Tool permissions. Whether a permission prompt can be raced the same way, and with what reply.
